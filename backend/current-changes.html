Gemini AI usage limits

Current workspace change summary for backend/app/services/ai_usage.py.

Daily request cap Monthly cost cap Error source labels

What changed

  • Usage-limit errors now carry a source identifier, defaulting to application_limit.
  • Configuration, usage-data, usage-store, and duplicate-request failures are tagged with distinct source values.
  • The daily request limit is enforced before a provider call. Reaching it raises a limit error tagged daily_request_limit.
  • The monthly reserved estimated-cost limit is enforced before a provider call. Exceeding it raises a limit error tagged monthly_cost_limit.
  • Invalid or non-positive daily and monthly limit settings disable AI requests with a configuration error.

Request flow

  1. Validate the request ID, limits, token cap, pricing, and research-cost inputs.
  2. Estimate and reserve usage against the daily request and monthly cost records.
  3. Block requests that exceed either configured cap or duplicate an already submitted request.
  4. Call the provider and settle the reservation from returned usage metadata.

Behavioral effect

Daily and monthly budget checks that were commented out are active again. Requests can be rejected before Gemini is called when a configured cap has been reached. Error source labels also make the reason for a rejection easier to identify programmatically.

Change scope

This markup documents only the current change captured in backend/usage-diff.txt. The change affects Gemini usage reservation and error classification in the backend.
